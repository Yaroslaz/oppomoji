# OPPOMoji

Лаборатория шрифтов для OPPO: диагностика наложений подчёркивания при включении Dai, предпросмотр OPPO Sans с выбранным весом и экспериментальная подготовка emoji-шрифта для установки через zFont 3.

**0.1.0-alpha — первая диагностическая сборка. Она ещё не решает задачу системной замены эмодзи с сохранением штатного ползунка веса. Исправление проблемы на Reno 16 Pro пока не подтверждено.**

## Скачать APK

Готовая сборка публикуется в [Releases](https://github.com/Yaroslaz/oppomoji/releases). Для каждого изменения `main` GitHub Actions также создаёт архив `OPPOMoji-apk` в [Build APK](https://github.com/Yaroslaz/oppomoji/actions/workflows/android.yml).

Это установочная development APK с debug-подписью. Она работает на Android 10 и новее; целевая версия — Android 16. Ключ development-подписи хранится в Actions cache. Если кеш ключа будет удалён, для установки следующей сборки может потребоваться удалить предыдущую.

## Что можно проверить

- Найти доступные файлы OPPO Sans в системных каталогах и сохранить локальную копию.
- Импортировать свой TTF/OTF текста и цветной emoji-шрифт.
- Сравнить русские буквы, подчёркивания и составные эмодзи в двух предпросмотрах.
- Менять вес текста внутри предпросмотра, если файл содержит ось `wght`.
- Взять метрики подчёркивания из OPPO Sans, настроить их и сохранить изменённую копию emoji-шрифта.
- Сохранить JSON с версией системы, текущими метриками Android, сведениями о выбранных шрифтах и доступными конфигурациями fallback.

Приложение работает без сети, root и разрешений на всё хранилище. Выбор и сохранение файлов идут через системный диалог. Отчёты и шрифты автоматически никуда не отправляются. В репозитории и APK нет шрифтов Apple или OPPO.

## Проверка на телефоне

1. Установи APK. Сначала выключи Dai, полностью закрой OPPOMoji и открой заново. Сохрани отчёт о совместимости.
2. Включи Dai тем способом, который уже работает со zFont 3. Снова полностью закрой и открой OPPOMoji; сохрани второй отчёт.
3. Найди OPPO Sans кнопкой в приложении. При необходимости выбери другой найденный файл: название не гарантирует наличие кириллицы или вариативного веса.
4. Если есть распакованный Android-совместимый emoji-шрифт TTF/OTF, открой его, возьми метрики из OPPO Sans и сравни строки.
5. Сохрани исправленную копию TTF и импортируй её в zFont 3. Используй уже работающий на твоей ColorOS способ применения.
6. Проверь отображение в настройках, сообщениях и браузере, а также штатный ползунок веса. При ухудшении верни стандартный шрифт и выключи Dai.

Для разбора нужны два отчёта и снимок реального наложения. Отчёт можно прочитать до отправки; он не содержит серийного номера, аккаунтов и содержимого переписки. Файлы шрифтов не включаются в отчёт. Не загружай личные файлы шрифтов в публичный репозиторий: используй локальные файлы или исключённый из Git каталог `private-fonts/`.

## Ограничения

На Android системный механизм обновления шрифтов защищён привилегированной подписью. Обычный APK не получает эти права, ADB/Shizuku сами по себе их не предоставляют. На поддерживаемых OPPO zFont использует возможности ColorOS, связанные с регионом Myanmar и поддержкой Dai. Поведение зависит от прошивки.

Цель дальнейшей работы — выяснить, позволяет ли конкретная прошивка менять только emoji fallback, сохраняя OPPO Sans и его регулировку. Пока такого подтверждённого пути для этого телефона нет. Приложения с собственным отрисовщиком или набором эмодзи могут игнорировать системную замену.

Редактор меняет только `post.underlinePosition` и `post.underlineThickness`. Таблицы глифов, `hhea`, `OS/2`, вариативные оси и межстрочные метрики сохраняются. Это проверяемая гипотеза, а не обещание устранить ошибку Dai: Android или приложение могут вычислять линию другим способом. Предпросмотр с отдельным fallback тоже не воспроизводит весь механизм Dai.

Исходный файл не перезаписывается. Контрольные суммы всех таблиц и `head.checkSumAdjustment` пересчитываются, старая `DSIG` удаляется. Шрифты с `MVAR` не редактируются этой версией, чтобы не повредить вариативные метрики. TTC, WOFF, ZIP и APK не распаковываются. `sbix` и SVG могут не поддерживаться конкретным Android-рендерером; исходный Apple Color Emoji не считается автоматически совместимым с Android.

## Сборка и проверки

Требуются JDK 17 и Android SDK с `platforms;android-36` и `build-tools;35.0.0`.

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

На Windows используй `gradlew.bat`. Путь к SDK задай через `ANDROID_HOME` или локальный `local.properties`.

CI проверяет редактор на повреждённых/перекрывающихся таблицах, пересчёт сумм, сохранность глифовых таблиц и отказ от неподдерживаемых форматов. Затем отдельная задача запускает APK и тесты импорта на эмуляторе Android 16. Проверка реального ColorOS остаётся обязательной: AOSP-эмулятор её не заменяет.

Источники: [системные шрифты AOSP](https://source.android.com/docs/core/fonts/custom-font-fallback), [Android CustomFallbackBuilder](https://developer.android.com/reference/android/graphics/Typeface.CustomFallbackBuilder), [таблица OpenType post](https://learn.microsoft.com/en-us/typography/opentype/spec/post), [совместимость zFont](https://zfont.app/help).
