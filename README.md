# OPPOMoji

Лаборатория шрифтов для OPPO: диагностика наложений подчёркивания при включении Dai, предпросмотр OPPO Sans с выбранным весом и экспериментальная подготовка emoji-шрифта для установки через zFont 3.

**0.1.5-alpha — экспериментальная сборка. Она ещё не решает задачу системной замены эмодзи с сохранением штатного ползунка веса. Исправление проблемы во всей системе Reno 16 Pro пока не подтверждено.**

В 0.1.1 поиск проверяет внутренние имена TTF/OTF/TTC, исключает Serif и отмечает файлы без кириллицы. Ползунки изменяют копию текстового шрифта, а не только emoji fallback. JSON сохраняется прямо в `Download/OPPOMoji` без системного выбора папки; при ошибке хранения его можно скопировать из окна приложения.

В 0.1.2 подписи интерфейса используют выбранный текстовый шрифт с кириллицей. Отдельный системный образец сохраняет поведение Dai, чтобы сравнение не скрывало проблему. В отчёте появились реальные расстояния между строками, метрики локали и файлы, которыми Android рисует фиксированные символы `A`, `Я`, `😀`. Кнопка чтения активных эмодзи на Android 12+ копирует найденный шрифт в приложение; его исходную и исправленную версии можно сохранить отдельно. Все экспорты идут прямо в Загрузки/OPPOMoji. Буфер обмена получает краткий JSON без длинных XML; файл содержит полный отчёт.

В 0.1.3 выбранный Sans автоматически получает активный системный emoji-шрифт в fallback, если свой файл не импортирован. Раньше `CustomFallbackBuilder` мог обращаться к штатным эмодзи, тогда как отдельный образец `Typeface.DEFAULT` показывал замену из zFont. Подключение активного шрифта не создаёт редактируемую копию: для исправления и экспорта остаётся кнопка «Взять активный emoji-шрифт из системы». Явный импорт имеет приоритет. Из поиска исключён `OPlus Sans Solid Digits VF`; EN с кириллицей предлагается перед SC/TC. Старый выбор Solid Digits при запуске заменяется доступным Sans с кириллицей, а если такого нет — снимается. Отчёт записывает источник emoji в предпросмотре и реальные файлы букв и эмодзи в каждом образце.

В 0.1.4 добавлена загрузка проверенного iOS-набора Emoji 17.0: 3 944 fully-qualified последовательности и 9 компонентов. Файл размером 35 322 044 байта скачивается только по кнопке с закреплённого коммита [dtingley11/KernelSU-iOS-Emoji](https://github.com/dtingley11/KernelSU-iOS-Emoji/tree/dd14ebd2db66fa4584a85876b002a6f1057dbc7f). SHA-256 проверяется до замены прежнего импорта. Это конвертация Apple-изображений на OpenType-структуре Noto; название таблицы `name` может остаться Noto Color Emoji. Полнота проверяется по данным Unicode, а не по названию файла. Предпросмотр содержит ☺️ ❤️ 😶‍🌫️ 🙂‍↕️ 🙂‍↔️ и новые Emoji 17.0.

В 0.1.5 найдена причина красной проверки Emoji 17.0 в 0.1.4. ©️ ®️ ‼️ ⁉️ ™️ #️⃣ 1️⃣ в предпросмотре рисовались текстовым шрифтом. Проверка на эмуляторе Android 16 показала, что виноват не iOS-набор. Свой emoji-шрифт приложение подключает через `Typeface.CustomFallbackBuilder`, а такое семейство нельзя пометить как emoji (`und-Zsye`): публичного API нет, скрытый метод недоступен. Поэтому символ, который есть и в текстовом шрифте, остаётся у текстового шрифта, даже с U+FE0F. Системное emoji-семейство помечено, и для того же Roboto оно забирает ©️ ™️ 1️⃣. Шрифт, установленный через zFont, становится системным. Проверка теперь проверяет такие последовательности на самом файле (emoji-шрифт первым) и записывает их в `textPresentationInCustomPreview`. Остальные последовательности по-прежнему должны рисоваться в предпросмотре. В отчёте появилось поле `claimsEmojiPresentation`. Оно показывает, объявляет ли выбранный OPPO Sans сам ©️ и другие последовательности с U+FE0F в `cmap` формата 14. Такой основной шрифт оставил бы их текстом и в системе.

Интерфейс 0.1.5 начинается с карточки «iOS-эмодзи для zFont». В ней показан образец эмодзи с текущими файлами, чек-лист из четырёх шагов и кнопка **«Подготовить iOS-эмодзи для zFont»**. Кнопка выполняет весь путь подряд и пропускает готовые шаги: находит OPPO Sans с кириллицей, загружает проверенный набор, переносит линию подчёркивания из OPPO Sans и сохраняет `OPPOMoji-iOS-emoji.ttf` в Загрузки/OPPOMoji. Строка статуса с полосой загрузки закреплена внизу экрана и видна при прокрутке. Редкие экспорты собраны в «Дополнительно». Исправленные копии больше не пересобираются, пока не изменились исходный файл или ползунки линии. Раньше изменение веса предпросмотра каждый раз переписывало 35 МБ.

Для применения: нажми «Подготовить iOS-эмодзи для zFont» и импортируй `Загрузки/OPPOMoji/OPPOMoji-iOS-emoji.ttf` через уже работающий способ zFont. Ручной путь остаётся: выбрать OPPO Sans, «Загрузить полный iOS-набор», «Взять метрики из OPPO Sans», затем «Сохранить emoji-шрифт для zFont» в разделе 04. Загрузка меняет предпросмотр и локальные копии, установка через zFont меняет систему. Приложения с собственным emoji-рендерером или EmojiCompat могут продолжить использовать свой набор; наличие глифов в TTF не управляет их клавиатурой или картинками.

## Скачать APK

Готовая сборка публикуется в [Releases](https://github.com/Yaroslaz/oppomoji/releases). Для каждого изменения `main` GitHub Actions также создаёт архив `OPPOMoji-apk` в [Build APK](https://github.com/Yaroslaz/oppomoji/actions/workflows/android.yml).

Это установочная development APK. Она работает на Android 10 и новее; целевая версия — Android 16. Начиная с 0.1.1, постоянный ключ development-подписи хранится в GitHub Actions Secrets, независимо от кешей. APK из Releases предназначены для последующих обновлений с сохранением данных.

При переходе с 0.1.0 нужно один раз удалить старое приложение: в первой сборке ключ не сохранился, и подпись отличается. Сбросятся локальные копии и настройки предпросмотра OPPOMoji. Сборки pull request и локальные сборки без настроенного ключа могут иметь другую подпись.

## Что можно проверить

- Найти доступные файлы OPPO Sans в системных каталогах и сохранить локальную копию.
- Импортировать свой TTF/OTF текста и цветной emoji-шрифт.
- Прочитать активный системный emoji-шрифт без поиска его файла вручную (Android 12+). Это системный выбор для `😀`, а не подтверждение происхождения пакета или покрытия всех эмодзи. ColorOS может ограничить доступ.
- Сравнить русские буквы, подчёркивания и составные эмодзи в двух предпросмотрах.
- Проверить обычное подчёркивание и цветную пометку орфографии в настоящих Android-полях ввода, как в присланном примере из мессенджера.
- Менять вес текста внутри предпросмотра, если файл содержит ось `wght`.
- Взять метрики подчёркивания из OPPO Sans, настроить их и сохранить изменённые копии текстового и emoji-шрифта. Они экспортируются отдельно; объединения в системный пакет пока нет.
- Сохранить JSON с версией системы, текущими метриками Android, сведениями о выбранных шрифтах и доступными конфигурациями fallback. Кнопка находится в разделе 04; окно отчёта позволяет скопировать JSON.

Обработка локальных шрифтов работает без сети, root и разрешений на всё хранилище. С 0.1.4 есть разрешение INTERNET для загрузки закреплённого набора по явному нажатию; автоматических загрузок, отправки отчётов или пользовательских шрифтов нет. Импорт файлов идёт через системный диалог; экспорт — через MediaStore в Загрузки/OPPOMoji. В репозитории и APK нет шрифтов Apple или OPPO.

## Проверка на телефоне

1. Установи APK. Сначала выключи Dai, полностью закрой OPPOMoji и открой заново. Сохрани отчёт о совместимости.
2. Включи Dai тем способом, который уже работает со zFont 3. Снова полностью закрой и открой OPPOMoji; сохрани второй отчёт.
3. Найди OPPO Sans кнопкой в приложении. Serif исключён из поиска. Файлы без кириллицы отмечены: русские буквы в них берутся из системного fallback. Если Sans недоступен, приложение явно сообщает об этом. Кнопка «Использовать активный системный шрифт» снимает прежнюю локальную замену текста.
4. При включённой замене из zFont нажми «Взять активный emoji-шрифт из системы». Если ColorOS не предоставила его, открой распакованный Android-совместимый emoji-шрифт TTF/OTF вручную. Возьми метрики из OPPO Sans и сравни строки.
5. Сохрани исправленную копию TTF и импортируй её в zFont 3. Используй уже работающий на твоей ColorOS способ применения.
6. Проверь отображение в настройках, сообщениях и браузере, а также штатный ползунок веса. При ухудшении верни стандартный шрифт и выключи Dai.

Для разбора нужны два отчёта и снимок реального наложения. Отчёт можно прочитать до отправки; он не содержит серийного номера, аккаунтов и содержимого переписки. Файлы шрифтов не включаются в отчёт. Не загружай личные файлы шрифтов в публичный репозиторий: используй локальные файлы или исключённый из Git каталог `private-fonts/`.

На полученных отчётах 0.1.1 с Reno 16 Pro масштаб текста одинаковый (0,9), выбранный OPPO Sans 4.0 EN содержит кириллицу и ось веса 100–700. Системная позиция подчёркивания при размере 100 px меняется с 15 до 60,742188 px; это смещение вниз. Ascent/descent при этом отличаются менее чем на 0,4 px. Скриншоты показывают большой межстрочный интервал системных подписей при нормальном интервале выбранного Sans. Эти данные подтверждают изменение системного отображения, но не устанавливают источник большого интервала: отчёты 0.1.1 не измеряли locale minimum и геометрию строк, emoji-файл не был выбран. Хвосты присланных через мессенджер XML обрезаны, поэтому сравнивать полные конфигурации по ним нельзя.

Полный отчёт 0.1.2 установил активный файл `/data/format_unclear/font/Customized-Regular.ttf`, семейство `Apple MFFM Color Emoji`, CBDT/CBLC, 35 291 248 байт. Его `post.underlinePosition=-1244` и `underlineThickness=131` при UPEM 2048 дают ровно системные 60,742188 и 6,3964844 px при размере 100 px. Совпадение указывает на источник системных метрик подчёркивания. Отрисованные `A` и `Я` при этом берутся из Roboto. В качестве локального текстового шрифта был выбран Solid Digits без кириллицы, а локального emoji-файла не было. Системный образец имеет шаг строк 96 px при размере 40,5 px, `localePreferredMinimum=false`, `explicitMinimum=null`, `elegantTextHeight=true`. Большой интервал подтверждён, но гипотеза о включённом locale minimum не подтвердилась; исправление `post` само по себе ещё не доказывает исправление интервала.

## Ограничения

На Android системный механизм обновления шрифтов защищён привилегированной подписью. Обычный APK не получает эти права, ADB/Shizuku сами по себе их не предоставляют. На поддерживаемых OPPO zFont использует возможности ColorOS, связанные с регионом Myanmar и поддержкой Dai. Поведение зависит от прошивки.

Цель дальнейшей работы — выяснить, позволяет ли конкретная прошивка менять только emoji fallback, сохраняя OPPO Sans и его регулировку. Пока такого подтверждённого пути для этого телефона нет. Приложения с собственным отрисовщиком или набором эмодзи могут игнорировать системную замену.

Редактор меняет `post.underlinePosition` и `post.underlineThickness` в текстовом и emoji-шрифте. Из MVAR убираются только записи `undo` и `unds`, чтобы они не перекрывали выбранные постоянные метрики. Остальные вариации метрик, таблицы глифов, `hhea`, `OS/2`, вариативные оси и межстрочные метрики сохраняются. Это проверяемая гипотеза, а не обещание устранить ошибку Dai. Цветную толщину SuggestionSpan задаёт Android; ползунок толщины относится к обычному подчёркиванию.

Исходный файл не перезаписывается. Контрольные суммы всех таблиц и `head.checkSumAdjustment` пересчитываются, старая `DSIG` удаляется. Из TTC извлекается выбранное семейство. WOFF, ZIP и APK не распаковываются. `sbix` и SVG могут не поддерживаться конкретным Android-рендерером; исходный Apple Color Emoji не считается автоматически совместимым с Android. Метаданные отчёта читаются выборочно, без загрузки больших таблиц цветных рисунков и без создания новых нативных семейств шрифтов.

## Сборка и проверки

Требуются JDK 17 и Android SDK с `platforms;android-36` и `build-tools;35.0.0`.

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

На Windows используй `gradlew.bat`. Путь к SDK задай через `ANDROID_HOME` или локальный `local.properties`.

CI проверяет редактор на повреждённых/перекрывающихся таблицах, пересчёт сумм, сохранность глифовых таблиц и отказ от неподдерживаемых форматов. Затем отдельная задача запускает APK и тесты импорта на эмуляторе Android 16. Проверка реального ColorOS остаётся обязательной: AOSP-эмулятор её не заменяет.

`tools/prepare_emoji.py` готовит локальную TTF-копию без публикации шрифтов в репозиторий: проверяет закреплённый SHA-256, все 3 953 записи из Unicode Emoji 17.0, наличие и непустоту PNG-битмапов, сохранность CBDT/CBLC/GSUB/cmap/hhea/OS/2 после изменения `post`. Требуются `fonttools==4.67.0`, `uharfbuzz==0.57.0`, `pillow==11.3.0`. Команда:

```sh
python tools/prepare_emoji.py --output ci-fonts/verified-emoji.ttf --report ci-fonts/coverage.json
```

Отдельный Android-тест проверяет кнопку «Подготовить iOS-эмодзи для zFont» без окна выбора файла. Сохранённый TTF должен получить линию из текстового шрифта. Эмодзи в предпросмотрах и образце должны рисоваться из emoji-шрифта, а цифры — из текстового.

Android-тест получает подготовленный файл в `getExternalFilesDir()/verified-emoji.ttf` и проверяет каждую запись в исходном и исправленном предпросмотрах: один видимый ненулевой глиф, отрисованный именно выбранным файлом, без подстановки системного Noto. Служебные глифы без видимой области записываются отдельно: наличие такого глифа само по себе не означает распад эмодзи. Unicode-список в `app/src/main/assets/` сопровождается Unicode License V3. Это проверка рендеринга и покрытия, а не доказательство происхождения каждого отдельного рисунка.

Источники: [системные шрифты AOSP](https://source.android.com/docs/core/fonts/custom-font-fallback), [Android CustomFallbackBuilder](https://developer.android.com/reference/android/graphics/Typeface.CustomFallbackBuilder), [таблица OpenType post](https://learn.microsoft.com/en-us/typography/opentype/spec/post), [совместимость zFont](https://zfont.app/help).
